# Алгоритмика — Python Exam Prep

Интерактивная русскоязычная платформа для однодневной подготовки к экзамену по алгоритмам на Python. Включает теорию, пошаговые визуализации, процедурно генерируемые задачи, редактор Monaco и исполнение Python в изолированном Pyodide Web Worker.

## Запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Сайт будет доступен по адресу, который выведет Vite (обычно `http://localhost:5173`). Первая загрузка Pyodide требует подключения к `cdn.jsdelivr.net`.

## Проверки

```bash
npm test
npm run build
```

Тесты проверяют воспроизводимость генерации и эталонные решатели, включая крайние случаи. Production-сборка создаётся в `dist/` и может быть размещена на любом статическом хостинге.

## Архитектура

- `src/lib/generators.ts` — seeded RNG, генераторы и независимые эталонные решатели.
- `src/workers/pyodide.worker.ts` — выполнение Python вне UI-потока.
- `src/lib/runner.ts` — таймаут и пересоздание worker.
- `src/components/Visualizer.tsx` — пошаговые визуальные модели.
- `src/components/Practice.tsx` — задачи, подсказки и progressive disclosure.

Условия модулей «Квартиры» и экзаменационно-специфической обработки строк намеренно не выдуманы: интерфейс резервирует их до получения оригинальных формулировок.

## Проверка Python-реализаций

Дополнительно к Node.js требуется Python 3 (только для разработки и тестирования):

```bash
npm run test:python
```

Команда генерирует воспроизводимые случаи во временный JSON, затем запускает все эталонные реализации в Python: 84 случая, включая крайние и увеличенные входы. Vitest отдельно сравнивает оптимизированные решатели с полным перебором на 100 seeds. Браузер использует только Pyodide, локальная установка Python пользователю сайта не нужна.

## Содержание и ограничения

- A, B, D: концепции, инварианты, базовый и оптимальный алгоритмы, пошаговые модели, проверка понимания, скрытые решения, практика.
- Все условия практики — явно обозначенные учебные модели. Оригинальные скриншоты отсутствуют; соответствие экзаменационным ограничениям не заявляется.
- C и E зарезервированы до получения точного условия.
- Семь режимов визуализации: массив, частоты, факторизация, окно, круговые индексы, два указателя, минимальная подстрока.
- Экзамен: три новые задачи, 90 минут, проверки, сводка и повторная попытка. Уход в другой раздел завершает попытку.
- Никаких localStorage, IndexedDB, cookies приложения, базы данных, API ИИ или сохранения решений. Состояние существует только в памяти React.
- Monaco и его worker поставляются в сборке. Pyodide 0.27.2 и WebAssembly загружаются с CDN. Полностью автономный офлайн-режим не реализован.
- На загрузку Python отводится 60 секунд, после загрузки — 5 секунд на запуск. Зависший worker завершается и создаётся заново. Стандартный ввод изолирован через StringIO, для каждого решения создаётся новое пространство имён.
- Проверка сравнивает строки после удаления внешних пробелов, CRLF → LF и удаления пробелов в конце каждой строки; внутренние пробелы значимы.
- Проверка не анализирует смысл произвольного кода: обратная связь основана только на запуске и сравнении результата.

## Развёртывание

```bash
npm ci
npm test
npm run test:python
npm run build
```

Разместите содержимое `dist/` на статическом HTTPS-хостинге. Основной хостинг проекта — GitHub Pages. Сервер Python или Node в production не требуется. При использовании CSP разрешите Web Workers, WebAssembly и загрузку Pyodide с `https://cdn.jsdelivr.net`.


## GitHub Pages и автоматические обновления

Адрес после включения Pages: https://frozzeh.github.io/python/

Workflow `.github/workflows/pages.yml` при каждом push в `main` устанавливает зависимости, запускает Vitest и Python-проверки, собирает Vite с базовым путём `/python/` и публикует `dist/` в GitHub Pages. Секреты вручную добавлять не нужно: используются штатные разрешения `GITHUB_TOKEN` и OIDC.

Для первого запуска в репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**, если автоматическое включение недоступно для токена Actions. После этого повторите workflow **Publish GitHub Pages** на вкладке Actions. В дальнейшем достаточно push в `main`.

Проверка production-сборки для Pages локально:

```bash
VITE_BASE_PATH=/python/ npm run build
npm run preview
```

Базовый путь применяется к JS, CSS, Monaco worker и Pyodide worker. При обычном `npm run dev` приложение по-прежнему открывается от `/`.
